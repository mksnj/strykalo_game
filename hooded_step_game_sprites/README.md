# Игровые спрайты: короткий шаг влево / вправо

Готовый **прозрачный PNG-спрайт-лист**, раздельные кадры и JSON-данные. Персонаж смотрит вперёд, руки в карманах, под капюшоном полностью чёрная пустота. Шаг небольшой. В момент завершения каждого шага ноги снова стоят ровно, в отличие от промежуточной фазы, где одна нога отставлена.

## Файлы

- `sprite_sheet.png` — атлас **4 колонки × 4 строки**, размер **1280 × 2432 px**; 13 кадров, последний блок пуст.
- `frames/frame_00.png` ... `frames/frame_12.png` — 13 отдельных кадров **320 × 608 px**, прозрачный фон RGBA.
- `animations.json` — точные координаты, кадры, порядок, длительность в миллисекундах, анимации `idle`, `step_left`, `step_right`, `side_to_side`.
- `atlas_phaser.json` — TexturePacker JSON Hash, подходит для стандартного загрузчика атласов Phaser 3.
- `preview_animation.gif` — демонстрационный GIF с серым фоном (фон **не** содержится в игровых PNG).
- `preview_contact_sheet.png` — 4 ключевых кадра на шахматном фоне.

## Логика анимаций

- `step_left`: кадры `00..06`. Стойка в центре → маленький шаг влево → приставление ноги → возвращение в центр.
- `step_right`: кадры `06..12`. Стойка в центре → маленький шаг вправо → приставление ноги → возвращение в центр.
- `side_to_side`: кадры `00..12`, повторение бесконечно. На `03` и `09` персонаж заканчивает шаг **с двумя ровными ногами**.
- `idle`: кадр `00`.

**Важно:** время воспроизведения у кадров разное (см. `animations.json`, `frames[].duration_ms`). Нельзя просто назначить всем 13 кадрам одинаковую скорость без изменения ощущения движения. Полный цикл = 2960 мс.

Позиция персонажа слегка меняется **внутри прозрачного PNG кадра** для видимого небольшого шага. НЕ применяйте дополнительно `shift_x_px` из JSON к координате игрового объекта в каждом кадре, иначе получится двойной сдвиг. Если нужен реальный сдвиг сущности по игровой карте, двигайте игровой объект отдельно через систему управления, а эти спрайты считайте in-place-анимацией.

Все кадры одного размера, центральное выравнивание; рекомендуемая точка привязки (origin/pivot) — `x=0.5`, `y=0.9671` (уровень обуви, около 588 px от верха). Не обрезайте каждый кадр по альфа-границам: это даст дрожание персонажа и «скачки» при проигрывании.

## Задание для Codex (скопировать)

> Добавь ассеты из пакета `hooded_step_game_sprites/` в мой проект и подключи их к существующему персонажу. Используй `sprite_sheet.png` как атлас и `animations.json` для точного порядка и индивидуальных длительностей кадров. Размер ячейки 320×608, 4 столбца; все кадры RGBA и имеют одну и ту же точку привязки (x=0.5, y=0.9671). Создай анимации `idle` (00), `step_left` (00–06, один раз), `step_right` (06–12, один раз) и `side_to_side` (00–12, loop). Сохрани текущие игровые input/physics и размер персонажа на экране. После шага влево и вправо обязательно используй фазу со сведёнными ногами (03 и 09), а не стоп-кадр с вытянутой ногой. Лицо и фон не рисуй. При необходимости адаптируй загрузку атласа к движку проекта. Не применяй дополнительно `shift_x_px` как world movement. В конце перечисли изменённые файлы и покажи, как запустить проверку анимации.

### Пример для любой 2D-библиотеки (псевдокод)

```js
const data = await fetch('/assets/hooded/animations.json').then(r => r.json());
const frames = data.frames;
let index = 0;
let elapsedMs = 0;
function update(deltaMs) {
  elapsedMs += deltaMs;
  while (elapsedMs >= frames[index].duration_ms) {
    elapsedMs -= frames[index].duration_ms;
    index = (index + 1) % frames.length;
  }
  const rect = frames[index].rect;
  // Нарисуйте прямоугольник rect из sprite_sheet.png в одном и том же месте на экране.
}
```

У JSON атласа 3 пустые ячейки в последней строке — это нормальная структура, не дополнительные кадры.
