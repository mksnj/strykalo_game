## Запуск и поставка

Атмосферная 2D-игра к десятилетию альбома «Развлечение» Валентина Стрыкало (2016–2026).
Текущая версия — **локальное браузерное демо** с полным игровым маршрутом; цель — Telegram Mini App.
Поддерживаются обе ориентации телефона, интерфейс и общение о разработке — по-русски.

В текущей редакции к площадке ведёт видимый проход; вход и выход — короткая смена планов без затемнения;
исправлены фантомная труба и вертикальный разрыв фона перед первой мини-игрой.
«Тени» — бегущий позади героя силуэт,
«О, брат» — медленно тонущий телевизор в тёмной коричневой луже за бордюром.
Дом с телевизором и статичный телевизор посреди дороги сняты с активной сцены.

Нужны Node.js **22.12+** и npm. Из корня проекта:

```sh
npm ci
npm run dev
```

Игра: `http://localhost:5173`. В Windows можно использовать `npm.cmd`.
Для отдельного локального запуска на использованном в проверках порту:
`npm run dev -- --host 127.0.0.1 --port 5175 --strictPort`, адрес — `http://127.0.0.1:5175/`.
Готовые WebP и восемь MP3 включены в проект; повторная генерация для запуска не нужна.
[.env.example](.env.example) содержит публичные настройки:

| Переменная | Назначение |
| --- | --- |
| `VITE_ALBUM_URL` | Ссылка на альбом; пустое значение отключает кнопку |
| `VITE_MINI_APP_URL` | Адрес игры в публикации; без него отправляется текст |
| `VITE_FINALE_AUDIO_URL` | Необязательная замена финальной музыки из `public/` или по HTTPS |

Секреты и токены в `VITE_*` запрещены. Сборка — `npm run build`, результат — `dist/`;
локальная проверка сборки — `npm run preview`.
`npm run archive:source` создаёт `tmp/strykalo-source.zip` на Windows или
`tmp/strykalo-source.tar.gz` на Linux/macOS, исключая зависимости, сборку, секреты,
служебные каталоги, кэши и результаты тестового раннера. После распаковки — `npm ci`.
На Windows состав и SHA-256 каждой записи ZIP проверяются; отчёт — `tmp/source-archive-audit.json`.
Локальный `node_modules/` нужен для разработки и в исходный архив не включается.

## Действующие правила

| Этап | Дистанция | Условие продолжения |
| --- | --- | --- |
| Ночной район | 0–200 | Подход к трубе |
| «Делать это трезвым» | 200 | 36 с активного баланса |
| Забор осеннего двора | 200–400 | Подход к площадке |
| «Бесполезно» | 400 | Пять попыток по три ошибки, затем сюжетная реакция |
| Тёмные дворы | 400–600 | Гром и дождь на бегу, затем непрерывный вход в комнату |
| «Решится само собой» | 600 | 90 с бездействия под дождём, затем 2 с покоя |
| Пустой финальный забег | 600–700 | Скамейка у подъезда |
| Подъезд | 700 | Отдых, подъём, вход и затемнение |

Мини-игры и переходы не увеличивают дистанцию. Единица дистанции — 60 px обычного маршрута.
Герой бежит автоматически; единственная команда раннера — прыжок.
Перед первым обычным забегом после загрузки страницы кнопка «Начать путь» открывает
короткий экран «Как играть»: четыре вида препятствий показаны игровыми изображениями,
их нужно перепрыгивать касанием экрана (на компьютере — пробел или ↑);
кассеты нужно собирать, каждая даёт одно очко. Забег начинается только после
«Понятно, в путь»; до этого дистанция, счёт и попытка не запускаются.
Кнопка «Назад» возвращает в меню. После подтверждения туториал не повторяется
до перезагрузки страницы; режим разработчика начинает игру сразу.

Тап даёт полный импульс **610 px/с** даже при отпускании между тиками;
удержание добавляет небольшой бонус первые **0,16 с**. Скорость 300 px/с (второй забег — постоянные 355,03 px/с), гравитация 1500 px/с²,
буфер **180 мс**, coyote time **120 мс**, двойного прыжка нет.

Собираются аудиокассеты: **одна = одно очко**, уникальные ID исключают повторную награду.
Внутренний ключ `tape` обозначает кассету. Опасности: бетонный блок `fence`, разбитый блок
`broken-block`, мусор `debris`, обломки `rubble` — по три размера; лужи как опасности удалены.
Коричневая лужа с телевизором во дворе за линией бега — безвредная отсылка без хитбокса.
Генерация по seed обязана быть проходимой коротким тапом. Первое препятствие — невысокий блок
после трёх кассет; первые 55 единиц проще, серии доступны с 110 и усиливаются к 500.
Перед переходами свободный участок. Кассеты чаще одиночные/парные, реже групповые.
Размеры, веса и интервалы вынесены в конфигурацию. Мусор увеличен вместе с хитбоксами:
`debris` 76×46 / 88×53 / 100×60, `rubble` 78×44 / 90×51 / 100×57.
Расчётное начало прыжка — за 90 px до переднего края; физика прыжка сохранена.

У игрока **3 жизни** на весь путь. Столкновение с препятствием в раннере снимает одну жизнь;
первые два не прерывают бег, третье завершает попытку. Одно препятствие снимает жизнь только один раз,
даже при перекрытии нескольких кадров. Остаток показан тремя сердцами в HUD и сохраняется между этапами.
Падение с трубы обнуляет жизни и завершает попытку.
В каждой из пяти ритм-попыток есть отдельный запас из трёх ошибок.
Первые четыре поражения дают повтор, пятое — сюжетную реакцию и продолжение пути,
сохраняя жизни раннера и счёт кассет.
Новая попытка и продолжение с контрольной точки восстанавливают все три жизни.
При достижении мини-игры сохраняется её контрольная точка **200/400/600** в `RunSession`:
идентификатор фазы, seed, дистанция и счёт. После падения с трубы **«Играть ещё раз»**
создаёт новый баланс прямо на трубе, открывает обучение и сохраняет кассеты до входа.
После завершения мини-игры точку заменяет начало следующего забега. Его продолжение
откатывает кассеты проигранного участка к сохранённому счёту, исключая накопление наград повторами.
**«С начала»** запускает новую попытку. До первой точки доступен только этот повтор.
Точки живут в памяти попытки и теряются при перезагрузке. В комнате искусственного поражения нет.
Рекорд — лучший локальный счёт на устройстве; он не защищён и не является общим рейтингом.

**Труба:** вид от первого лица над городской строительной выемкой, инерция, ветер и
постепенно усиливающаяся неустойчивость. Нужно удержаться 36 с. Успех продолжает раннер,
падение даёт Game Over. Широкий закатный фон с тяжёлыми коричнево-охристыми облаками,
отдельная труба; дальних зданий в первом лице нет. Боковая труба — прямой участок без загнутых опор; декоративные бетонные
блоки на берегах удалены. Маска разрыва дороги учитывает широкое окно.
В боковом уличном плане двор непрерывно виден за котлованом: маска выемки не вырезает
вертикальные полосы в фоне. Отдельного фасада с телевизором больше нет.
Передний план имеет отдельную маску: ветви и провода над землёй сохраняются,
нижний мусор не перекрывает котлован. Кирпичная стенка с лестницей заменена срезом грунта.
Переднего тумана, проецируемых стен и движущихся материалов нет. Координаты трубы и грунта
обновляются даже за экраном; смена ширины окна и возврат к началу не показывают старую геометрию.

**Предупреждение перед мини-игрой 2.** До **30.10.2026 08:00 UTC+03** и обычный маршрут,
и кнопка **«Мини-игра 2»** в главном меню открывают окно **«Звезд пока нет»** с текстом
**«По прогнозам, звездопад начнется 30.10 в 08:00»**.
**«Пройти на площадку на свой страх и риск»** открывает обучение мини-игры 2;
**«Пройти дальше»** ведёт через обычный выход к третьему забегу, сохраняя кассеты и жизни.
Ровно с даты открытия экран автоматически заменяется обучением без перезагрузки, включая возврат из фона.
Проверка стоит в переходе сессии, использует клиентские часы, допускает внедрение серверных часов
через `RunSession.now` и не является защищённым серверным ограничением.
Экран обходят только сокращённый режим разработчика и вход через dev-список «Тестирование этапов».

**«Бесполезно»: пять попыток по три ошибки.** Четыре дорожки с падающими
звёздами-стрелками и неподвижными целями **← ↓ ↑ →**.
Нет фиксированного лимита длительности и завершения по времени: новые ноты
создаются непрерывно, пока игрок не допустит три ошибки в текущей попытке.
Начальный пролёт — 2,1 с (падение примерно на 14% медленнее v14), появление — каждые 1,2 с
в начальном темпе вместо 2,45 с. Затем каждые 2 с прибавляется 10% **начальной**
скорости: ×1,0 в начале, ×1,5 через 10 с, ×2,0 через 20 с, ×3,0 через 40 с.
Это линейное ускорение по примеру владельца, не сложный процент.
Ускоряются и падение уже видимых звёзд, и частота появления; в точках ускорения
позиция не перескакивает. Первая цель достигается примерно через 2,41 с.

Окна попадания: **±90 мс** «Вовремя», **±240 мс** «Почти в такт».
Ошибкой считается пропуск или неверное/несвоевременное нажатие по видимой звезде.
Одна звезда отнимает не более одной попытки: неверное нажатие и последующий
пролёт не дают двойной штраф. Нажатие при отсутствии активной звезды не штрафуется.
В HUD видны ошибки 0/3 и текущая скорость.
Удержание клавиши и autorepeat не играют следующие ноты.
Ноты и реакции используют ограниченные пулы, а не бесконечно растущую историю.

Герой стоит анфас. Стрелки/WASD и четыре экранные кнопки дают отдельные нажатия.
Обучение, пауза и фон не расходуют время. Музыка начинается после «Начать →»;
используется её непрерывное время, в том числе после зацикливания трека.
Недоступный или остановившийся звук включает резервное активное время.
Нет автоматического исчезновения земли по таймеру: её вид зависит от оставшихся ошибок.
После первых четырёх поражений — «Ещё раз» на 1,25 с активного времени, затем
новые ноты, нулевые ошибки/попадания и перезапуск музыки. Счётчик попыток скрыт.
После пятого поражения — строго «бесполезно», реакция 3,8 с, выход 4,6 с и checkpoint 400/40.

**Вход под дождём:** отдельная фаза остановки перед домом удалена.
Гром и дождь начинаются ещё в раннере, герой остаётся на экране и продолжает бег.
Внешний вход использует тот же объект спрайта, что раннер: без исчезновения
и повторного появления. Непогода начинается на секунду раньше v14: за 1,12 с до
перехода из раннера. Двери герой достигает примерно через 2,56 с от начала непогоды,
смена плана на интерьер происходит примерно через 2,92 с.
Затем завершается вход и начинается третья мини-игра.
Гроза, дождь за окном и приглушённые раскаты продолжаются все 90 секунд бездействия.
Сброс ожидания продлевает дождь: общее прошедшее время его не выключает.
После 90 с непогода прекращается, герой ещё 2 с сидит спокойно, затем выходит
и продолжает финальный бег. Пауза/фон останавливают и ожидание, и погоду.

**Комната:** герой сидит на табуретке; небольшие часы, отдельная дверь и надпись
«Пусть решится само собой». Нужно **90 с без игрового ввода**.

| Бездействие | Событие |
| --- | --- |
| 10–15 с | Взгляд на часы |
| 25 с | Мерцание лампы |
| 65 с | Звук часов |
| 90 с | Конец непогоды; ещё 2 с покоя, затем открытие двери и выход |

Игровое нажатие обнуляет ожидание и очередь событий; удержание не даёт копить время.
Касания люстры, окна, часов, героя и двери не сбрасывают ожидание. Люстра дважды приглушает
свет во всей комнате, остальные предметы дают локальные реакции. В окне видны дождь
и вспышки, нарисованных молний нет. Надпись «Пусть решится само собой» — блеклое граффити без свечения.
Клик/тап именно по двери показывает «Ты куда-то торопишься?» на 4 с активного времени,
последняя секунда — плавное исчезновение. Повторное нажатие продлевает единственную фразу.
Клавиши, фон и другие предметы эту фразу не вызывают; ожидание и очередь событий от двери не сбрасываются.
Часы продолжают ход при сбросе. Крупного обратного отсчёта нет.
Кот и прохожий удалены прежним согласованным изменением, события 45/85 с отсутствуют.

**Финал:** на 600–700 нет опасностей, кассет и прыжкового управления. Затем:
замедление 1,8 с → посадка 1 с → отдых **6 с** с тремя выдохами → подъём 0,9 с → бег к двери 1,6 с →
вход 1 с → затемнение 2 с. Финальный фасад — жилой подъезд:
прямоугольная приоткрытая дверь, тёмный лестничный тамбур, без сквозного прохода во двор. Камера и фасад не перескакивают; музыка финала начинается у скамейки.
Герой сидит анфас, локти на коленях; вход больше не уменьшает его спрайт.
Надпись «Ты куда-то торопишься» после комнаты и у скамейки удалена.
Результат «Путь домой завершён»: счёт, рекорд, повтор, публикация, ссылка на альбом;
кнопка рейтинга объясняет ограничения демо. Лампа мерцает, `prefers-reduced-motion` фиксирует свет.

Визуальная отсылка к «92» удалена: нет пары, указателя и номера на фасаде.
Сохранены огонёк «Ускользает», телевизор «О, брат», труба, звёзды, тень, комната и подъезд.
На 460–496 один силуэт бежит **позади** героя на расстоянии 92 px,
повторяет кадры бега и прыжки с задержкой **280 мс**. Он того же масштаба, стоит вертикально,
не выходит вперёд и не меняет поверхность. Появление занимает 460–465,
исчезновение — 481–496; до этого силуэт сохраняет постоянную непрозрачность.
Пауза останавливает движение и исчезновение; повтор очищает историю. Проекции на асфальт и прохода больше нет.
Около 80 (8 в коротком маршруте) старый телевизор медленно тонет в коричневой луже
на заднем плане двора за бордюром. Лужа 150×37,5 и корпус 88×66 — отдельные прозрачные
изображения, слой расположен за дорогой, поверхность воды на Y=416, нижний край касается
дорожки за бордюром перед началом дорожного полотна (Y=435).
Параллакс 0,42 совпадает с двором: лужа не скользит относительно гаражей и деревьев.
Холодное затемнение корпуса `0x7b8793` и воды `0x727b84` приглушает экран и тёплые блики;
прозрачность корпуса не уменьшается, меньший масштаб отделяет его от игрового плана.
За 6 с активного времени с первого появления в кадре корпус опускается на 58 px;
неподвижная вода скрывает погружённую часть, без растворения или мигания. Телевизор не всплывает заново.
Пауза останавливает погружение, новый забег сбрасывает его. Отсылка остаётся далеко позади
края выемки перед трубой и не связана с фасадом.
Эти эпизоды безвредны и не прерывают раннер.

**«Для разработчика»:** маршрут делится на 10, препятствия отключены, мини-игры на
20/40/60, конец 70. Длительности/исходы мини-игр сохранены; музыкальные границы масштабируются.
Режим доступен только через Vite dev, выключен после перезагрузки; результат не меняет рекорд и не публикуется.
Прямой вход через «Тестирование этапов» — отдельная функция с полными дистанциями,
семью точками входа и необязательным uint32 seed; она не использует routeDivisor.
«К этапам» возвращает в меню даже из обучения. Полный список этапов и сокращённый режим
скрыты в production. Три отдельные кнопки **«Мини-игра 1/2/3»** доступны в главном меню
также в production: это изолированные прямые запуски без сохранения рекорда и публикации результата.

## Экран, ввод и пауза

Мир 960×540, линия земли/стоп **Y=438**, фиксированный шаг **1/120 с**.
В portrait HUD сверху, окно игры 4:3, управление снизу. Камера раннера показывает 720 мировых px
с 600 px впереди героя (2 с реакции), звёзд — 800, комнаты/финала — 960.
ResizeObserver, safe-area и динамическая высота окна учитываются, сессия не пересоздаётся.
В landscape ширина мира `max(960, 540 × ширина_окна / высота_окна)`.
Тайловые дворы продолжаются; затемнения закрывают всю ширину.
Панорамы трубы/комнаты 1920×640 при высоте 540 занимают 1620 px вокруг X=480.
На более широком окне равномерный cover-масштаб допускает небольшую вертикальную обрезку.
Предметы комнаты масштабируются вместе с фоном; сама труба сохраняет игровой масштаб.
Зеркальных копий этих фонов нет. Финальный фасад продолжают только сплошные фрагменты кладки:
подъезд и лампа не повторяются, чёрные клинья исходного края не используются.

| Режим | Управление |
| --- | --- |
| Раннер | Касание всей игровой области, Space или ↑; удержание увеличивает прыжок |
| Труба | Левая/правая половина игровой области, A/D или ←/→; экранных стрелок нет |
| Ритм | Отдельные нажатия ← ↓ ↑ → / WASD или четырёх экранных кнопок |
| Комната | Отсутствие игрового ввода; системный UI и четыре интерактивных предмета не сбрасывают таймер |

Pointer Events охватывают свободные поля и пассивный HUD, исключают кнопки, ссылки,
настройки, подписи полей и редактируемые элементы. Захват указателя сохраняет удержание;
перенос через центр на трубе меняет направление, отпускание ритм-клавиши разрешает следующее отдельное нажатие.
Отпускание вне области, cancel, lostpointercapture, пауза, фон, blur и смена сцены очищают ввод.
Поворот, фон и потеря фокуса ставят игру на паузу: время не считается, звук приостанавливается,
счёт/дистанция/таймеры сохраняются. Продолжение явное и доступно в обеих ориентациях.

## Графика и ресурсы

Холодный постсоветский город, меланхолия, одиночество и лёгкий сюрреализм; мягкая рисованная 2D-графика
с коллажной фактурой. Палитра `#111822`, `#222B39`, `#384557`, `#667487`, `#858EA1`, `#A2A6B0`.
Без пиксель-арта, фотореализма, яркой мультяшности, уютного золотого света и чрезмерного хоррора.
Герой — обычный человек в тёмном худи с рюкзаком, поднятым капюшоном и скрытым лицом.
Локальные акценты: приглушённый закат в балансировании, старая лампа и блеклое граффити комнаты.
Подъезд освещён чуть сильнее, но вход не должен казаться уютным/безопасным.

Слои: дальний город → двор/фасады → игровой план → прозрачный передний план → слабая фактура.

параллакс 0,16 / 0,42 / 1 / 1,12. Герой, угрозы и награды всегда читаемы, декор их не закрывает.

тень перенесена на 460–496. Труба (36 с), ожидание (90+2 с), жизни и финальные сцены сохранены.

`RunSession.starsDefeats` считает ровно пять поражений. Каждое — три ошибки.
После первых четырёх фаза `stars-retry` длится 1,25 с; затем новый `StarsEngine`,
очищенный ввод и новая музыкальная эпоха `starsRound`. `RunnerScene` сбрасывает
музыкальный канал **до следующего физического тика**. Обучение повторно не открывается;
пауза/фон останавливают реакцию, музыку и симуляцию. Только пятое поражение показывает
строго **«бесполезно»** на 3,8 с, затем обычный выход и checkpoint 400.

Герой анфас увеличен со 110 до **154** (+40%). Исследованы исходные прозрачные поля:
`hero-front` 128×256, видимое тело Y=7…254; беговые кадры 128×128, Y=16…127.
Вход/выход используют поправку отношения видимых высот, чтобы смена текстуры
не меняла видимый рост. Анфасный рисунок разделён на торс и две ноги с опорой у бёдер:
шаги и небольшая работа корпуса следуют попаданиям/ошибкам, idle — дыханию;
`prefers-reduced-motion` уменьшает движения в пять раз. Целый персонаж при этом не вращается.
Это составная анимация исходного единственного кадра: новых ракурсов стоп/сгибания коленей нет.
Ритм-поле X=270…495 остаётся слева от героя X=640.

**Музыкальная постановка — предварительная калибровка.** Исследован именно
`03-92.mp3`, SHA-256 и измерения: [отчёт сигнала](docs/previews/gameplay-v17/audio-analysis.json).
`node tools/analyze-autumn-score.mjs` воспроизводит анализ через ffmpeg: low-pass 180 Hz,
RMS 50 мс с шагом 10 мс. Выбраны сильные равномерные акценты **39,61 / 41,06 / 42,52 с**;
промежутки 1,45/1,46 с позволяют приземлиться перед каждым следующим прыжком.
Энергетические изменения около 3/25/49 с — лишь кандидаты границ частей,
**они не подтверждают первый куплет, припев и начало второго куплета**.
Прослушивание в текущей среде недоступно, поэтому требование закончить до второго куплета
и соответствие «груб — груб — груб» остаются для окончательной проверки на слух.

`AUTUMN_SCORE` в `game/config.ts` централизует параметры: старт музыки 4,6 с
на `pipe-exit`, начало собственно второго забега на 7,0 с композиции, скорость
**300 px/с**, подготовка 500 px, посадочный просвет 350 px, три блока 72×24.
Забег ровно 200 единиц с существующим замедлением заканчивается примерно на **48,73 с** трека.
Для прямого входа и checkpoint музыка однократно выравнивается на 7,0 с;
последующее аудио не меняет координаты препятствий. Задержка декодирования/буферизации
может дать слышимое отклонение; fallback продолжает игру при недоступном звуке.
После прослушивания править `musicStartSeconds`, `jumpMarkers` и кандидаты частей;
проверять, что все блоки остаются до безопасной зоны перехода.

`runner/autumnSequence.ts` вычисляет три постоянные мировые координаты.
`WorldGenerator` исключает случайные препятствия и кассеты из всей защищённой области,
выдаёт каждый постановочный блок один раз при любом seed. Последовательность сохраняется
при продолжении с 200. Сокращённый маршрут разработчика остаётся без препятствий.

**Прямой вход:** `npm run dev` → меню → **«Тестирование этапов»** → seed (необязательно) →
любой из семи этапов. Мини-игры сразу создаются со своими движками и управлением;

В главном меню, **включая production-сборку**, постоянно видны отдельные кнопки **«Мини-игра 1»**
(труба), **«Мини-игра 2»** (звёзды), **«Мини-игра 3»** (комната): раскрывать список этапов не нужно.
Они используют тот же прямой запуск и seed из списка этапов, если он задан.

Жизни 3, счёт 0; тестовые результаты не изменяют рекорд и не отправляются через «Поделиться».

### Три ошибки, ускорение и непрерывный вход в дом · v14 · 29.10.2026

Вторая мини-игра больше не имеет таймера завершения. Ноты генерируются по мере
прохождения; 3 ошибки заканчивают мини-игру и запускают её сюжетное продолжение.
`rhythmTiming.ts` интегрирует скорость, поэтому уже падающие звёзды ускоряются
без скачков позиции. Формула — `1 + 0.1 × floor(t / 2)`: через 20 с падение
и появление вдвое быстрее начального. Начальный пролёт сокращён с 3,4 до 1,8 с.

другому спрайту при входе. Теперь гроза начинается на последних шагах раннера;
после него сразу идёт `room-approach`, использующий тот же объект героя.

проёме при переходе к интерьеру, а не перед домом.

В комнате дождь и гроза продолжаются до успешных 90 секунд бездействия.
Игровой сброс ожидания не прекращает дождь. Затем `room-rest` оставляет героя
на месте ещё 2 с: погода затихает, после чего начинается обычный выход и бег.

ближняя ограда Y=408; тротуар Y=420…434. Ограда охватывает X=145…855 с небольшим
боковым расширением у зрителя; доступный герою прямоугольник находится внутри неё.

Проходы шириной 130 px расположены около X=260 и X=780; в них нет сетки и бордюра.

согласовано с осью ключа. Кольцо 107,52×179,2 с равномерным масштабом 0,28;
высота кромки ~134 px соотнесена с ростом героя на дальней плоскости и ориентиром 3,05 м.

Сначала игровая глубина переводится в каноническую: Yc=100+(Ygame−356)×2,1.
Затем вся земля проецируется вокруг линии улицы:
**Yview=438+(Yc−438)×(0,25+0,75F)**, где F — общий фокус камеры от 0 до 1.
Он же определяет опоры ограды, кольца, города, разметки, листьев и UV общего асфальта.
Вертикальные изображения героя, дома и кольца сохраняют пропорции. Низ земли не
поднимается к фасаду: это изменение ракурса плоскости с постоянной уличной опорой.
Маска асфальта, второй накладной пол и растушёвка двух покрытий не используются.
UV асфальта у Y=438 всегда равен 716, независимо от F; горизонтальная фаза следует
общему сдвигу мира. Кэш дальнего города дополнен только отражёнными строками верхних
128 px неба, чтобы камера не открывала пустой верх. Пиксели города и исходные WebP сохранены.

| Камера | Поведение |
| --- | --- |
| RUNNER | Обычная улица; F=0, верх кадра 0 |
| COURT_ENTRY | Сначала бег к X=260, затем поворот через проход; F и вертикальный кадр меняются непрерывно |
| COURT_ACTIVE | F=1; верх −115 в landscape / −170 в portrait; камера не следует за героем |

Выходной путь перераспределён в прежних 4,6 с; художественное продвижение мира 1100 px
не увеличивает игровую дистанцию. Конечная скорость камеры снова 300 px/с.

<details><summary>Исторические требования v5/v6 — заменены самостоятельной сценой v9</summary>

<a id="court-visual-fix"></a>
### Площадка: исходный дефект и критерии визуальной приёмки

**Исходная редакция `court-world-v5`: НЕ ПРИНЯТА.** Скриншот пользователя после неё
показывает баскетбольную площадку, воспринимаемую как поверхность у жилых этажей,
несоразмерно высокий щит/кольцо, чужеродную ограду и перекрывающуюся геометрическую разметку.
Это оценка **видимого результата**, а не утверждение о точной причине в коде: перед
исправлением нужно проверить фактическую отрисовку актуальной рабочей копии проекта.
Проход между домом и площадкой и отсутствие пиксельного пересечения сами по себе
**не доказывают** правильную перспективу или общий масштаб.

**Целевая композиция.** Герой движется вдоль обычной улицы, проходит рядом с домом,
входит через читаемую калитку/проход и оказывается на старой дворовой площадке.
Дом и площадка стоят на одной логической отметке уровня земли. Часть дальней плоскости
в 2D-кадре может находиться выше на экране из-за перспективы, но не должна выглядеть
физически поднятой платформой у стены. Поверхность не пересекает дом, фундамент,
проход или вертикальные объекты и не образует диагонального «накладного» пласта.

**Единый масштаб и глубина.** Прежде чем править отдельные числа, проверить систему
world → camera → screen, опорные точки/контакт с землёй, порядок слоёв и взаимный масштаб
дома, героя, кольца и ограды. Высоту кольца оценивать относительно героя **на той же
плоскости глубины**, а не относительно персонажа, стоящего заметно ближе к камере.
Для игровой сцены допустима условная перспектива, но вертикальные конструкции должны
оставаться вертикальными, их основания — стоять на покрытии. Если геометрия существующего
изображения не позволяет этого добиться, разделить/переработать графику, не растягивая
объекты по осям и не меняя физику.

**Разметка и ограда.** Использовать одну геометрически связную схему **полуплощадки с
одним кольцом** либо менее подробные выцветшие линии, близкие по характеру исходному
`location-v7/court.webp`. Не накладывать два центральных круга или несколько несовместимых
«ключей». Все линии должны лежать на одной плоскости с разумным перспективным
сокращением; сетка должна иметь реальный вход, опоры на землю и читаемую связь секций.

**Запрещённые обходы.** Не скрывать дефект feather/градиентом/маской, затемнением,
искусственным подъёмом асфальта, случайным X/Y-сдвигом, независимым увеличением кольца
или простым масштабированием всей композиции. Не возвращать асфальт как вторую накладку.

**Порядок приёмки (все этапы обязательны):**

1. Сначала один реальный кадр из работающего Phaser без HUD, одновременно показывающий
   дом, основание дома, героя, калитку и значительную часть площадки. Визуально оценить
   относительную высоту земли, контактные точки, масштаб кольца, форму разметки и ограды.
2. Затем реальные кадры входа 0/20/40/60/80/100%, активной арены и выхода, без скачков
   масштаба, положения и слоя; проверить обычный и короткий маршрут.
3. Отдельно проверить 960×540, 1920×1080, 1230×372 и 375×667; арена остаётся удобной
   для уклонения от звёзд, не уменьшается ради красивой картинки.
4. Пересмотреть изображения человеком или визуально, а не только алгоритмами пересечений:
   автоматические тесты с правильными координатами могут не заметить плохой перспективы,
   непропорционального кольца и ложного ощущения высоты земли.
5. Только после визуальной приёмки запускать остальные регрессионные проверки и обновлять
   статус здесь; ссылки на фактически созданные скриншоты записывать в `docs/previews/`.

**Неприкосновенно:** один спрайт героя, прыжок на границе, вход 4,8 с, выход 4,6 с,
реальное попадание звезды и порог 15 с, игровая площадь, непрерывная камера без
затемнения, правила счёта/дистанции, мобильное управление и остальные мини-игры.

## Звук и установка записей

Активны восемь предоставленных владельцем MP3, установленных без перекодирования
в `apps/web/public/audio/user-instrumentals/` (68 087 420 байт, длительности 193–424 с).

| Имя MP3 | Когда играет |
| --- | --- |
| `01-uskolszaet.mp3` | «Ускользает», 0–99 |
| `02-o-brat.mp3` | «О, брат», 100–199 |
| `03-92.mp3` | «92», после трубы и обучение перед ритмом |
| `04-delat-eto-trezvym.mp3` | «Делать это трезвым», подход к трубе и баланс |
| `05-teni.mp3` | «Тени», после звёзд, 400–599 |
| `06-bespolezno.mp3` | «Бесполезно», после подтверждения обучения: ритм и реакция |
| `07-reshitsya-samo-soboy.mp3` | «Решится само собой», подход к комнате, ожидание, выход, финальный забег |
| `08-podvorotnya-moy-dom.mp3` | «Подворотня — мой дом», действие у скамейки и вход в подъезд |

Каталог — `game/audio/catalog.ts`, привязки — `installedInstrumentals.json`.
`StreamingMusicChannel.ts` воспроизводит музыку через HTMLAudioElement в общем Web Audio микшере,
без полного декодирования в AudioBuffer; `BufferLibrary.ts` и `LoopChannel.ts` обслуживают короткие звуки/петли.
Кроссфейд **1,4 с** начинается после старта новой дорожки; музыка зациклена, пауза сохраняет позицию.
Первый жест разблокирует звук, заблокированный autoplay повторяется следующим жестом.
Устаревшие каналы, запросы и источники освобождаются; недоступное аудио не блокирует игру.

Три независимые громкости: музыка **85%**, окружение **15%**, эффекты **60%** по умолчанию;
значения и mute сохраняются локально. Шаги, ветер, скрип трубы, тиканье и звук старой лампы — окружение;
кассета, прыжок/приземление, удары, бой часов и дверь — эффекты. Максимум 12 коротких эффектов,
одинаковый звук не накладывается на себя; звёздный шум ограничен интервалом 220 мс.
`GameplaySoundscape.ts` следует событиям симуляции; звук не меняет механику.
После Game Over музыка останавливается, удару даётся до 1,2 с; после финала музыка звучит в результатах,
в меню останавливается. Настройки звука не являются игровым вводом.

Резерв `original-v1/`: пять оригинальных тем по 24 с, четыре петли по 12 с, 14 эффектов;
23 звука × OGG/MP3 = 46 файлов. Пустой слот использует резерв, недоступный установленный MP3 — MP3-резерв сцены.
`VITE_FINALE_AUDIO_URL` имеет приоритет для финала в том же микшере.

Для обновления создайте `instrumentals/` и положите свои записи под именами из таблицы
либо русскими названиями песен, например `Тени (минус).mp3`:

```sh
node tools/install-instrumentals.mjs ./instrumentals
```

Можно передать другой путь в кавычках. MP3 копируются без перекодирования; OGG/WAV/FLAC/M4A/AAC
конвертируются в MP3 192 кбит/с. Нужны `ffprobe` и, для конвертации, `ffmpeg` в PATH.
Импортёр проверяет имена, дубликаты и длительности до копирования; частичная установка сохраняет остальные слоты.
Обновляются файлы и манифест, после чего перезапустите Vite/пересоберите production.
Откат на резерв: манифест `{}`, затем перезапуск/сборка; ненужные импортированные файлы можно убрать.
`node tools/generate-audio.mjs` (нужен ffmpeg) генерирует только оригинальный резерв,
не изменяет записи владельца; промежуточные WAV/измерения — в `tmp/audio/`.

<a id="architecture"></a>
## Архитектура

TypeScript, Phaser 3, React и Vite; новых зависимостей без необходимости не добавлять.
Пути в таблице относительно `apps/web/src/`:

| Модуль | Ответственность |
| --- | --- |
| `ui/`, `services/` | React-меню/HUD/результаты, локальный рекорд, настройки и публикация |
| `game/config.ts`, `game/runner/generationConfig.ts` | Физика, маршрут, мини-игры и генерация |
| `game/runner/` | Независимые физика, коллизии, seed-генерация и объекты |
| `game/minigames/{balance,stars,waiting}/` | Независимые симуляции мини-игр |
| `game/state/RunSession.ts`, `route.ts`, `store.ts` | Попытка, переходы, checkpoints и состояние UI |
| `game/scenes/RunnerScene.ts`, `game/views/` | Жизненный цикл Phaser и отображения |
| `game/input/`, `viewport.ts` | Игровой ввод и камера, отдельно от системного UI |
| `game/assets/`, `game/audio/` | Реестр/загрузка графики, каналы и звуковые события |

`packages/shared/src/contracts.ts` содержит контракты будущих авторизации, попыток и рейтинга;
`tests/unit/` — Vitest, `tests/browser/` — Playwright, `tests/fixtures/` — изолированные представления.
React не управляет физикой; представления не меняют симуляцию. Phaser использует одну активную сцену.
Одинаковый seed и ввод воспроизводят попытку. Комната считает целые тики; фон/пауза время не добавляют.
Объекты за экраном удаляются; пулы, история тени, эффекты и обработчики ограничены/освобождаются.
`MiniGameOutcome` различает фатальное и сюжетное поражение, `RunResult.reason='completed'` завершает путь.

## Инструкции разработчику

1. Перед работой прочитайте этот файл, соответствующий код и текущий Git-статус, если Git доступен.
   Не пересоздавайте реализованные функции. Единственный источник актуальных сведений — этот README;
   исправления правил, статуса и плана вносите сюда. В других `.md` остаются короткие указатели/лицензия.
2. Сохраняйте изложенные механику, атмосферу и разделение модулей. Параметры держите в конфигурации;
   избегайте постороннего рефакторинга. Расхождение кода/документа разрешайте явно,
   без молчаливой подмены механики. Работайте по одному этапу, оставляя проект запускаемым.
   Следующий этап требует разрешения; явный запрос на исправления уже задаёт разрешённый объём.
3. Сохраняйте оригиналы, точные промпты и лицензии; добавляйте provenance в `assets/source/provenance.json`.
   Не скачивайте защищённые записи и не создавайте узнаваемые имитации песен.
   Не возвращайте снятые игровые объекты на основании старых промптов/отчётов.
4. Проверяйте релевантные тесты, TypeScript, ссылки и сборку; линт — если появится конфигурация.
   Приоритет: отзывчивость прыжка, коллизии/счёт, seed-проходимость, тайминги, переходы,
   touch/ориентации, WebView, производительность и освобождение ресурсов.
5. Обновите этот README после значимого изменения. Исторические результаты можно хранить
   в JSON, не добавляя конкурирующие Markdown-спецификации. Сообщайте, что изменено,
   что реально проверено и что осталось открытым; не выдавайте прежние проверки за новые.

Будущий сервер должен проверять подпись/срок Telegram initData, регистрировать пользователя,
выдавать seed/ID попытки и проверять ввод/результат на сервере. Клиентским Telegram ID и очкам не доверять;
исключить повторное завершение и награды, валидировать запросы, ограничивать частоту.
Админские маршруты и экспорт защищать серверными правами. Секреты — только серверные переменные;
не логировать credentials/initData, хранить минимум данных. Деморекорд не переносить в общий рейтинг.
