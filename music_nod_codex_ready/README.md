# Music nod — готовые спрайты для игры

Ритмичный **небольшой кивок головой под музыку**, 8 кадров с прозрачностью (RGBA).
Ноги стоят на месте, руки в карманах, лицо полностью скрыто в чёрной тени капюшона.

## Файлы

- `frames/nod_00.png` — `frames/nod_07.png`: 8 самостоятельных кадров по **320×608**.
- `sprite_sheet_4x2.png`: основной атлас, **1280×1216**, 4 столбца × 2 строки.
- `sprite_sheet_8x1.png`: альтернативная полоса, **2560×608**, 8 кадров в ряд.
- `atlas.json`: координаты кадров для основного атласа (TexturePacker-like JSON Hash).
- `animation.json`: порядок кадров, длительности, точка привязки и синхронизация с BPM.
- `preview.gif`: проверка анимации, не использовать как игровую текстуру.
- `preview_frames.png`: просмотр всех кадров.
- `CODEX_TASK.md`: готовое задание для Codex — передай его вместе с папкой.

## Правила импорта

1. Использовать PNG с альфой, **не GIF** и не контактный лист.
2. НЕ обрезать/не триммировать каждый кадр по отдельности; все 320×608 на одном канвасе.
3. Кадры идут по индексам 0–7 слева направо, сверху вниз (для 4×2).
4. Весь цикл 8 кадров / 1000 мс при 120 BPM; два кивка за цикл, нижние точки 2 и 6.
5. Центр ступней — x≈160, линия опоры — y≈588 в кадре. Для точки опоры используйте (0.5, 588/608). Если у игры уже есть точка привязки персонажа, сохраняйте её и компенсируйте разницу, избегая скачка между анимациями.
6. Если известен BPM трека, масштабируйте скорость: `fps = 8 * BPM / 120`. Ещё точнее — синхронизировать по музыкальной временной позиции, как описано в `animation.json`.
7. Добавить как отдельное состояние `music_nod`, не ломая существующие `idle`, `step_left`, `step_right` и пользовательское управление.

PNG-изображения содержат мягкую полупрозрачность по краям; включайте обычный alpha blending. Рекомендуется предварительно визуально проверить в контексте игры при фактическом игровом масштабе.
